## 1. Что за продукт

IITALY — сервис поступления в итальянские университеты для школьников из
Казахстана 16–18 лет и их родителей. Один платёж 25 000 ₸ вместо
650 000 – 1 000 000 ₸ у агентств. ИИ ведёт по маршруту: подбор вузов,
документы, стипендия DSU, виза D, первые недели в Италии.

**Аудитория определяет почти все технические решения:** телефон 390px,
медленный мобильный интернет в регионах, недорогие Android. Каждый раз,
когда встаёт выбор «красивее или легче», выигрывает легче.

Сайт живёт на `https://iitaly.kz`, репозиторий
`bashpayy-hash/iitaly-site`, есть второй — `bashpayy-hash/iitaly`.

## 2. Стек и как всё устроено

- **Next.js 16.3.4**, App Router, Turbopack, `output: "export"` — статика,
  серверной части у фронтенда нет.
- **React 19.2**, TypeScript, **Tailwind v4** (токены в `@theme` внутри
  `src/app/globals.css`), **motion** v13 (наследник Framer Motion).
- Шрифты — `next/font/google`: **Onest** (весь продукт) и **Space Mono**
  (только технические подписи). Скачиваются на наш домен при сборке.
- Деплой — **Netlify** по `netlify.toml`: `npm run build`, каталог `out`,
  Node 22.

```bash
npm install
cp .env.example .env.local
npm run dev            # http://localhost:3000
npx tsc --noEmit && npm run lint && npm run build
npx serve out -l 4321  # посмотреть ровно то, что увидит хостинг
```

## 3. Правила, которые нельзя нарушать

1. **Бэкенд не трогать.** Node/Express на Railway, в этом репозитории его
   нет. Фронтенд только читает адрес из `NEXT_PUBLIC_BACKEND_URL`
   (единственная точка — `src/lib/backend.ts`). Контракты:
   ```
   POST /api/chat · /api/check-document · /api/order · /api/lead · /api/event
   GET  /api/portal/:code?surname=
   POST /api/portal/:code/task · /doc · /notify · /delete
   ```
2. **Тексты, цены и фактуру не менять** без прямой просьбы. Цена
   25 000 ₸, стипендия до €7 557, 43 университета в 30 городах — это
   данные, а не копирайт.
3. **`DESIGN.md` — источник правды по визуальному языку.** Перед правкой
   интерфейса читать его. Менять его вместе с кодом, а не после.
4. **Ветка.** Разработка в `claude/improve-website-design-ylr1p1`, оттуда
   PR в `main`. Прямо в `main` не пушить.
5. **Иллюстрации.** Не показывать сгенерированный текст, неправильные
   названия вузов и артефакты генерации. Не приписывать кадру место,
   которого в нём нет. Не ставить крупные изображения в FAQ, блок
   доверия, форму диагностики, тарифную карточку, рядом с оплатой и
   поверх информации о возврате.

## 5. Что уже сделано

Всё смержено в `main`. Крупными блоками:

- Перенос со старого одностраничного сайта на Next.js: токены,
  типографика, секции, личный кабинет.
- Бумажный слой: две `feTurbulence`-текстуры на взаимно простых тайлах
  (149px и 617px), умножение на светлом и screen на тёмном.
- Редакторские метки: приводочные крестики, волосяные направляющие,
  микроподписи Space Mono. **Метки несут только реальные факты IITALY и
  никогда — критичную информацию.**
- Иллюстрации: фоновые подложки с двойной маской и вклейки в рамке.
- Маскот Веспа: 18 поз, движение в двух уровнях (внутри SVG и через
  `VespaReveal`).
- Доступность: skip-link, `<main id="main">`, видимый фокус везде,
  `aria-live` на динамике, вкладки кабинета через `tablist/tab/tabpanel`.
- `prefers-reduced-motion`, `prefers-reduced-transparency`,
  `prefers-contrast`.
- SEO: `canonical` на всех семи страницах, свои `title`/`description`, OG.
- Вес по кеглю: `display` 500, `title` 600, ниже 22px без изменений.
- Первый экран: Веспа как объект-герой, заголовок из-под маски, липкая
  подача, переходы куполом между разделами.
- Скетчбук городов под картой (порт механики ThreeUI, MIT).

## 6. Грабли, на которые уже наступали

Каждая стоила отладки. Не наступай второй раз.

**Tailwind preflight ставит `img { max-width: 100% }`.** Это зажимает
любую ширину больше 100% у картинок. В скетчбуке половина разворота с
`width: 200%` показывала всю страницу сплющенной вдвое, и на экране это
читалось как утроение оттиска. Лечится `max-width: none`.

**Классы CSS-модуля с одинаковыми именами схлопываются.** `.next` для
зоны листания и `.curl.next` для направления изгиба — один и тот же
сгенерированный класс, и `right: 0` от зоны ломал `left: 50%` у листа.
Давай зонам собственные имена.

**Lightning CSS схлопывает `backdrop-filter` с `-webkit-` и может
выбросить стандартное свойство.** Не переопределяй его напрямую —
сбрасывай переменную Tailwind: `--tw-backdrop-blur: initial`.

**`:last-child` ломается, когда каждый пункт обёрнут в свою обёртку.**
Обёртка между `<ol>` и `<li>` делает каждый пункт единственным ребёнком,
и `:last-child` совпадает со всеми сразу. У `Reveal` для этого есть
`as="li"`.

**Структуру motion-пропов нельзя менять от `prefers-reduced-motion` —
только длительность.** Контекст известен лишь после монтирования; если
снять `animate` по условию, Motion не откатит стили и элемент застынет
невидимым навсегда.

**У липкого элемента `useScroll({ target })` замирает на нуле** — после
прилипания его прямоугольник перестаёт двигаться. Считай от
`useScroll().scrollY`.

**Круговой `border-radius` не виден на полноширинном блоке.** 64px на
листе шириной 1440px трогают по 64px с краёв. Нужен эллиптический:
`50% 50% 0 0 / 5.5rem 5.5rem 0 0`. И `overflow: hidden` обязан висеть на
том же элементе, что несёт радиус.

**Эмуляция `prefers-reduced-motion` через CDP не доходит до документа
внутри `<img>` с SVG.** Внутри файла медиазапрос работает у настоящих
пользователей — проверяй флагом браузера, а не эмуляцией.

**`html { scroll-behavior: smooth }` ломает полностраничные скриншоты** —
секции с появлением по прокрутке выходят пустыми. Снимай по экранам.

**`pkill -f "serve out"` убивает родительскую оболочку** — шаблон
совпадает с её же командной строкой. Используй `fuser -k 4321/tcp`.

**Не определяй слои по именам классов в `elementFromPoint`** — легко
поймать похожий класс из другой ветки. Помечай ветки `data-*` и ищи по
ним.

**`threeui.com` закрыт сетевой политикой, но npm-реестр идёт в обход
прокси.** Исходники оттуда достаются через
`curl https://registry.npmjs.org/<пакет>` и распаковку тарбола. Так был
получен и сверен по SHA-256 исходник скетчбука.

## 7. Как проверять

Playwright и Chromium уже стоят, качать ничего не надо.

```bash
# скрипты запускать из корня проекта — playwright резолвится оттуда
npm run build && npx serve out -l 4321 &
node ./_check.mjs        # chromium.launch({ executablePath:
                         #   "/opt/pw-browsers/chromium-1194/chrome-linux/chrome" })

CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
  npx lighthouse@12 http://127.0.0.1:4321/ \
  --only-categories=accessibility,seo,performance,best-practices \
  --chrome-flags="--headless --no-sandbox" --output=json --output-path=lh.json
```

Обязательный минимум перед PR: `npx tsc --noEmit`, `npm run lint`,
`npm run build`, осмотр на **390×844** и **1440×900**, проверка
горизонтального переполнения **попыткой сдвига** (`window.scrollTo(400,0)`
и сравнить `scrollX`), а не сравнением `scrollWidth` — на `/privacy`
`scrollWidth` показывает 394 при 390, но страница не прокручивается.

## 8. Открытые хвосты

- **Ветка `claude/illustration-system` висит на origin.** Прокси
  отказывается её удалять (`remote end hung up`). Снести кнопкой в
  веб-интерфейсе GitHub.
- **В корне лежат `index.html`, `privacy.html`, `tokens.css`,
  `robots.txt`** — предыдущая версия сайта одним файлом, оставлена
  намеренно как справочный материал. В сборку не попадает. Внимание:
  аудиты, снятые с `index.html`, к живому сайту отношения не имеют — на
  этом уже один раз сгорело время.
- **Скетчбук ограничен разрешением исходников.** Максимум 896px по
  ширине, и лупа увеличивает ещё в 2.3 раза. Если захочется девять
  разворотов вместо семи или крупнее — нужны новые иллюстрации, в
  сессии для этого есть Higgsfield MCP (оригинал приёма тоже сделан им).

## 9. Тон работы, которого ждёт заказчик

Общение по-русски. Ценит, когда:

- сначала измеряют, потом утверждают — числа, а не впечатления;
- проверяют в браузере и показывают скриншот, а не «должно работать»;
- прямо говорят, что премиса задачи не сходится, вместо того чтобы молча
  сделать не то (так уже было дважды: аудит по мёртвому файлу и бриф,
  описывавший давно перенесённое состояние);
- комментарий в коде объясняет **почему**, а не пересказывает код —
  особенно про неудачные попытки, чтобы их не повторили;
- отказ делать что-то вредное звучит один раз и с предложением
  ближайшей рабочей альтернативы.
