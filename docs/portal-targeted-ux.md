Точные сроки показываются только при наличии корректной даты в данных выбранного вуза. Текущий каталог содержит указания сверяться с конкурсом программы, поэтому отсчёт дней сейчас не показывается. Плановые ориентиры из маршрута не превращаются в дедлайны подачи.

Автоматического уведомления об изменении требований в системе нет. Вместо неподкреплённого обещания «мы сообщим» дано действие: «Уточнить требования выбранного вуза и проверить документ повторно».

## Предложение для пункта 8, без реализации

Публичный экран: `/progress#<случайный_токен>`. Фрагмент адреса не отправляется серверу страницы и в заголовке Referer. Статический экран запрашивает только разрешённые поля через `POST /api/progress-share/lookup`, передавая токен в теле запроса.

Запись ссылки: `id`, `student_id`, `token_hash`, `created_at`, `expires_at`, `revoked_at`. В базе хранится хеш случайного токена из 32 байт. Создание и отзыв доступны только владельцу через существующую проверку доступа к кабинету. Новый выпуск заменяет прежнюю ссылку. Предлагаемый срок действия: 90 дней, с возможностью выпустить новую.

История прогресса: `student_id`, `task_id`, `event_type`, `occurred_at`. Нужна отдельная история событий, чтобы блок «За последние 7 дней» показывал реальные действия, а не дату последней загрузки страницы. Старые события не восстанавливаются догадками.

Разрешённый ответ: только имя без фамилии, названия вузов, этапы и их прогресс, плановый ориентир с явной подписью, обезличенные названия действий за 7 дней. Не возвращать документы, ссылки на файлы, отчёты проверок, контакты, ответы анкеты и учётные данные.

В маршруте: «Поделиться с родителями». В настройках: дата выпуска и «Отозвать ссылку». После отзыва или истечения срока экран сообщает, что ссылка недоступна. Отсутствие документов проверяется на уровне серверного ответа, а не только скрытием UI. Код пункта 8 требует отдельного подтверждения пользователя.
