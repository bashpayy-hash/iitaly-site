в справочнике, каталоге, плане, ценах и личном кабинете.

Общий язык здесь — роли, композиция и поведение помощника. Это **не смена
палитры**: опубликованные цвета, токены, шрифты, фоны и редакционные

форму / начертание логотипа: `iItaly`, без точки, первая строчная `i` в
капсуле существующего фирменного красного, `Italy` — существующим шрифтом
полужирного начертания. Этот знак должен быть общим для шапки, подвала,
кабинета и иконок. Это не разрешение менять остальные шрифты или цвета.

## API компонента

`BrandLogo({ compact?, className? })` содержит только визуальный знак.
Его внешняя ссылка или размеченный элемент сохраняет доступное имя IITALY
и текущий переход; в кабинете нажатие по-прежнему открывает обзор внутри
приложения. Иконки используют первый знак, не миниатюрную длинную надпись.

```tsx
import { VespiAssistant } from "@/components/mascot/VespiAssistant";

<VespiAssistant
  variant="inspector"
  layout="editorial-callout"
  appearance="portrait"
  aria-label="Совет Веспи"
  label="Веспи · помогу разобраться"
  message="Сверим комплект перед подачей."
>
  {/* Существующее действие и фактические ограничения принадлежат странице. */}
</VespiAssistant>
```

| Prop | Значения / поведение |
| --- | --- |
| `variant` | `route`, `inspector`, `celebrate`, `copilot`; по умолчанию `copilot` |
| `layout` | `inline-pill`, `editorial-callout`, `portal-copilot`, `floating-bar`; по умолчанию `inline-pill` |
| `appearance` | `portrait`, `figure`, `indicator`, `none`; у `inline-pill` по умолчанию индикатор, у остальных портрет |
| `as` | `aside` по умолчанию; `div` для вложенного состояния / существующего region |
| `label`, `title`, `message`, `children` | Короткая атрибуция, необязательный заголовок, реплика, существующее содержимое / действие |
| `className`, HTML-атрибуты | Оформление текущего маршрута, `aria-label`, `hidden`, тестовые атрибуты |
| `priority` | Ранняя загрузка уже имеющейся локальной картинки там, где она нужна в первом экране |

`VespiAssistant` не отправляет вопросы, не запускает проверку, не закрывает
шаг, не вычисляет вердикт и не решает, когда показывать sticky. Это
ответственность владеющего экраном компонента. Добавление персонажа само
по себе не создаёт дополнительную кнопку.

Для отдельного изображения `Vespi` принимает те же четыре роли и
`presentation="portrait" | "figure"`. Старые `variant="avatar" | "ride"`
сохранены для действующих мест использования.

## Роль не означает новый рисунок

| Роль | Контекст | Ассеты сейчас |
| --- | --- | --- |
| `route` | Поиск направления, университеты, выбор учебного маршрута | Принятые `vespi-avatar-route-*` и `vespi-ride-route-*` |
| `inspector` | Апостиль, перевод, заявка, загрузка, разбор документа | Те же утверждённые изображения через явный fallback |
| `copilot` | Следующий шаг, вопросы анкеты, объяснение маршрута | Те же утверждённые изображения через явный fallback |
| `celebrate` | Уже полученный результат / завершённый шаг | Те же утверждённые изображения; не обещание поступления |

Новые очки, документ в руке, жест и анимационный ролик **не генерировались**.
В `VESPI_ROLE_ASSETS` специальные роли пока имеют пустые записи: компонент
выбирает имеющийся портрет или фигуру и выставляет
`data-vespi-fallback="approved-original"`. Нет ссылок на несуществующие файлы.

После получения новой графики: проверить лицо и красный шлем, обрезку в 72–96px,
прозрачность, читаемость и отсутствие официальной печати; подготовить локальные
WebP с реальными размерами; добавить соответствующую пару `src` / `srcSet`
в реестр роли. Не менять принимающие страницы. Отдельно проверить реальный
экспорт, вес и reduced-motion fallback, если добавляется видео. Три готовых
брифа для Higgsfield остаются в `../vespi-meta-guides/higgsfield-prompts.md`.

## Композиция и присутствие

- `inline-pill`: короткая реплика с тихим «ИИ» или без изображения. Главная
  страница использует этот режим под уже существующим героем.
- `editorial-callout`: портрет 96px на компьютере / 72px на телефоне с мягким
  выходом за край. Текст сохраняет ширину; он не превращается в узкую колонку
  ради картинки. Фон и обводка берутся из текущей поверхности.
- `portal-copilot`: вопрос или реальное состояние рядом с портретом. Текущий
  экран сам сохраняет единственное доступное действие и ограничения шага.
- `floating-bar`: компактная композиция нижней плашки. Компонент не фиксируется
  сам — размещение, видимость и безопасные отступы задаёт `/guides`.

Общий launcher использует `IntersectionObserver` и `MutationObserver`, чтобы
заметить видимый `img[data-vespi]` вне самого чата. Когда персонаж уже есть в
контенте, в launcher остаётся индикатор «ИИ» с тем же доступным действием.
Внутренний портрет открытого чата не считается вторым содержательным блоком.
Никаких периодических запросов, scroll polling или автоматической отправки
сообщений не добавляется.

На `/guides` поиск всегда содержит индикатор. Портрет совета крупнее, у каждой
темы своя смысловая роль. Нижняя плашка появляется только после Hero, пока
открытая статья видна и **весь** её совет вместе с выступающим портретом вне
видимости. У совета есть упреждающая зона 140px; поэтому плашка уходит ещё до
соприкосновения двух композиций. Сохраняются скрытие при открытом помощнике,
фокусе поля, открытом мобильном меню и низком viewport, ручное закрытие и
отступ над служебным бейджем. Контекст `/plan?fromGuide=…` сохраняется.

## Кабинет: один маршрут и реальные состояния

Новый banner не дублирует дорогу. Существующая закреплённая дорога остаётся
источником текущего этапа, названия действия, исполнителя и имеющегося
ориентира. На обзоре персонаж едет по ней; в подробном шаге / разборе документа
персонаж живёт рядом с содержимым, а на дороге остаётся маленький маркер.

Будущий шаг объясняет предшествующее действие и остаётся без выполнения или
загрузки. Родительский исполнитель, готовность, исходные даты и самоотчёт
берутся из текущих функций кабинета. Числа оставшихся дней не дописываются
из предположений. Встроенный выбор вузов сохраняет карту и сравнение без
предложения уйти из кабинета в `/plan`.

`inspector` показывает полученный результат проверки, причину и следующий
шаг. Пять статусов, точность формулировок, найденные проблемы и источники не
меняются ради более дружелюбного голоса. Отсутствие данных не становится
ошибкой файла. Повторная загрузка, право её выполнять и закрытие шага остаются
за прежней логикой; персонаж не создаёт «одобрение» от вуза или консульства.

В пустом списке документов и завершённом / отсутствующем плане используется
смысловое пояснение с индикатором, чтобы не дублировать персонажа на дороге.

## План: объяснение вопроса вместо нового опроса

Существующие 10 вопросов и значения ответов не меняются. `QUESTION_CONTEXT`
связывает каждую реплику с настоящим смыслом ответа:

| ID | Зачем вопрос |
| --- | --- |
| `intake` | Разделять правила разных наборов |
| `education` | Определить образовательный маршрут, сохраняя решение за вузом |
| `grades` | Описать профиль без прогноза поступления |
| `goal` | Разделять бакалавриат и магистратуру |
| `budget` | Планировать расходы отдельно от стипендии и визовых средств |
| `field` | Уточнять тесты и конкурс у программы |
| `lang` | Понять подготовку / подтверждение языка |
| `age` | Учесть отдельные действия родителей для несовершеннолетнего |
| `residence` | Выбрать процедуру по месту законного проживания |
| `dsuRegion` | Сверять документы по конкретному конкурсу стипендии |

Сохранение черновика, фактические состояния чтения и проверки файла,
бесплатный лимит и действующие платёжные переходы сохранены. Реплики при
обработке отражают состояние компонента; выдуманных процентов или времени нет.
